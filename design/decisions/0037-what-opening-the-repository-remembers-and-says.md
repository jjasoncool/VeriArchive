# What opening the repository remembers and says

Every command, and the GUI when it starts, opens the repository as §B7.4 says: the one named with `--repository` or `VERIARCHIVE_REPOSITORY` (explicit), else the one pinned in the config file, else, on first use, a new one that `repo init` pins. R-83 step 5 then compares the opened repository's uuid with the config's `last_repository_uuid`, warns where they differ, and records the new uuid.

That comparison was made for every repository opened, also one named for a single command. The user guide's own example, an import into another repository (`--repository <other> repo init`, then `import`), wrote the other repository's uuid into the pin's record, even with a read-only command such as `--repository <other> archive list`; the next plain command, on the pinned repository, then warned "repository_uuid changed from ... to ...; recorded the new uuid", and so did every switch back and forth. `repo init --repository P` beside an existing pin created P and wrote P's uuid into the config file the same way, although it left the pin as it was. The warning was true to the letter of step 5 and false to its purpose: it is meant to tell that the repository behind the pin has been replaced (another copy of the folder, a repository restored from an older backup, a disk swapped), and here nothing had been replaced.

## Decision

1. **The record belongs to the pin.** R-83 step 5 applies to the pinned repository only (`repo_selected_by` is `pinned`): where its `repository.json` names another uuid than the config's `last_repository_uuid`, the program warns and records the new uuid, as before. A repository chosen with `--repository` or `VERIARCHIVE_REPOSITORY` is never compared with that record and never written into it, whatever the command, so using one once leaves the next command on the pinned repository without a warning. An init that pins a repository (the first use, or `repo init --repository P` while nothing is pinned) writes the pin and, as its record, the new repository's uuid, as before; `repo init --repository P` beside an existing pin creates P and leaves the config file as it is.

2. **A repository that cannot be opened is named.** Where the repository chosen by step 1 or 2 is missing or holds no valid `repository.json` (exit 11, never a fallback), the message names its path, and for the pinned one the config file that names it: "the configured repository P is unavailable or is not a VeriArchive repository (the config file C names it)", "VERIARCHIVE_REPOSITORY names the repository P, which is unavailable or is not a VeriArchive repository", or, for `--repository`, "the repository P is unavailable or is not a VeriArchive repository". It said "configured repository is unavailable or is not a VeriArchive repository" in every case, so the operator could not tell which disk to attach, nor that an environment variable chose the place.

3. **The warning of an elevated run comes first, always** (R-12). The warning "VeriArchive is running elevated; repository and home resolution may differ" was added only to a session that had opened its repository, so it was missing exactly where it explains the most: an elevated run finds another home folder and another user config file, and so may find no repository, or another one, and then failed without it. It now comes before anything else from every command that opens the repository, also where the repository cannot be opened (the CLI prints it before the error; the GUI's Settings shows it under the reason no repository is open), and from `media list`, which opens no repository.

4. **The program shows its version.** Nothing showed which version runs: `--version` printed the usage (exit 10), and neither `repo info` nor the GUI did, although manifests (`created_by.app_version`) and the history (`verify_runs.app_version`) record it, the guides speak of earlier versions, and an update unzips a new version over the old folder. Now `veriarchive-cli --version` prints "VeriArchive version 1.0.0" (exit 0; `--json`: `{"app_version": "1.0.0"}`), `repo info` adds the line "program version: 1.0.0" (`app_version` in its `--json`, the name the manifests and the history use), and the GUI's Settings view shows "Program version: 1.0.0" as its first line, also while no repository is open; each in either language. The version is the build's (`PROJECT_VERSION`), the one manifests record. "Program version" in words, as the glossary keeps "version" from meaning a revision.

## Why

The record says which repository the pin last led to. Only opening the repository through the pin can tell that what the pin leads to has changed; a repository named for one command says nothing about it, and writing its uuid into the record made the record wrong for the next plain command. Leaving the record alone keeps the warning for the case it was made for: the folder behind the pin replaced by another repository.

Rejected alternatives:

- Keeping one record per repository (a list of uuids): the warning would then say only that a repository is new to this config file, which it cannot know usefully for a folder named on the command line; the pin is the one place whose content is expected to stay the same.
- Warning for an explicit repository without recording its uuid: every command with `--repository` would warn, about a repository the operator named on purpose.

## Consequences

- Amended by decision 0046 (point 4): the GUI's Settings shows the program's version in its last group, About, beside R-02's sentence, where it was the first line, also while no repository is open; the owner approved that layout in the prototype of the window. `01-settings.png` and `07-language.png` show the page from its top.
- `--repository` and `VERIARCHIVE_REPOSITORY` no longer write the config file at all: neither the record nor, as before, the pin.
- The user guide's example of an import into another repository names that repository with `--repository`, which it lacked, and works without a later warning.
- Tests of point 4: the CLI end to end: `--version` in either language and in `--json`, and `repo info` in either language and in `--json`, each showing the build's version, which the test is given. A mutation check removed `--version` and the version from `repo info` in turn, and each removal failed the test. The Settings view has no test of its own (GTK); its screenshots in the guides (`01-settings.png`, `07-language.png`) still show it without the version until `tools/screenshots` takes them again.
- Tests of point 3: a session that cannot be opened (an explicit config file that does not exist) and one that opens (a repository named with `--repository`), each with the warning first where the process runs elevated and without it where it does not; the elevation is given by the test (`SessionOptions::elevated`), as no test system can run elevated and unelevated at once. A mutation check left the warning out of the session that cannot be opened, and the test failed. The CLI's printing of it and `media list` have no test of their own: the end-to-end test cannot make the process elevated, and leaves the warning out of what it compares where CI runs elevated.
- Tests of point 2: the pinned repository that is gone, named with its path and its config file, and a missing repository named with `--repository` and with `VERIARCHIVE_REPOSITORY`, each in its own words, and each translated. A mutation check dropped the path from each message, and each removal failed the test meant for it.
- Tests: a repository created and opened with `--repository` beside a pinned one leaves the config file byte for byte as it was and gives no warning, nor does the pinned repository opened plainly afterwards; one named by `VERIARCHIVE_REPOSITORY` the same; the pinned repository whose uuid changed still warns and is recorded (R-83 step 5); the CLI end to end: a plain `repo info` after a command on another repository named with `--repository` prints no warning. A mutation check removed each rule in turn (the comparison made for the pinned repository alone; the config written by an init only where it pins), and each removal failed the test meant for it.
